# ADR 0001 — Per-device usage JSONL with read-time merge

- 状态：已采纳
- 日期：2026-11-11

## 背景

`/tools` 需要按使用次数排序，数据必须：

- 跨设备汇总（同一用户多台机器、WSL 与宿主、容器与宿主）
- 可被同步工具带走而不互相覆盖（Dropbox / git / 手动拷贝）
- 崩溃时最多丢一轮，不丢整段历史
- 数据量足够小，能长期保留

## 决定

- 存储介质是 **JSONL**，一行一条**聚合增量**：
  `{"v":1,"ts":"<iso>","device":"<device>","tool":"bash","count":12,"errors":1}`
- 一台设备一个文件：`usage-<设备名>.jsonl`；设备名取 `PI_DEVICE_NAME` 或主机名，小写并把非法字符折叠成 `-`。
- 进程内累加，`turn_end` 与 `session_shutdown` 时把每个变化过的工具刷成一行追加写入；写失败保留待写批次，下次重试。
- 读取时扫描目录下全部 `usage-*.jsonl`，按**精确工具名**求和 `count` / `errors`，`lastUsed` 取最大 `ts`。
- 只统计**真正执行**的调用（`tool_execution_end` 带 `durationMs`）；被禁用拦截的调用没有执行，不计数。

## 备选方案与放弃原因

- **一次调用一行**：明细最全，但一次会话几千行，与「长期保留」冲突。
- **每设备单文件整体重写**（`usage.json` 对象）：多设备同步时会互相覆盖，正是要避免的失败模式。
- **记录「设备+天+工具」聚合**：写之前得先读同 key 的最后一行再续写，重写风险与上面的单文件问题同类。

## 后果

- 多设备之间无需协调写：各写各的文件，只读时合并。
- 机器改名会产生新设备文件，计数仍正确；反之文件被手工改名/复制也不会让统计出错，因为 `device` 字段在记录里。
- 删除分两级：只删本设备（默认）或删全部设备（`clear all`），避免误删他人历史。
- 时间轴只保留到「每次 flush 的 ts」，够做趋势，做不了逐秒审计——这是刻意的取舍。
